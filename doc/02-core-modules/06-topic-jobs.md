# 主题任务

## 这篇文档解决什么问题

这篇文档帮助你理解：主题任务页不是“看看规则列表”的地方，而是**把规则真正运行起来，批量产出主题的执行页**。

规则管理解决的是“主题从哪里来”；主题任务解决的是“现在开始按这条规则跑一批主题”。

---

## 模块用途

主题任务是主生产链路里的第一层批量执行页。它负责：

1. 从已存在规则中选择来源
2. 提交一批主题生成任务
3. 监控这些任务的进度与状态
4. 对失败任务做重试、暂停、恢复或清理

它是规则管理和主题管理之间的桥梁。

---

## 适用场景

你最适合在这些情况下进入主题任务页：

- 规则已经准备好，想开始批量生成主题
- 想观察某批主题任务当前进度
- 某批任务失败，需要重试失败项
- 想暂停或恢复某批任务
- 想查看当前哪些规则已经被用于运行任务

---

## 页面入口

- **菜单名称**：主题任务
- **页面 slug**：`yali-ai-writer-topic-jobs`
- **后台 URL**：`admin.php?page=yali-ai-writer-topic-jobs`

这是一个“创建任务 + 查看任务列表”合并在同一页里的页面。

---

## 页面结构

## 一、创建主题任务表单

页面上方是新建任务区。当前已确认的核心字段包括：

- 规则选择
- 主题数量

这说明它不是复杂的高级调度页，而是一个非常明确的批量执行入口：**选规则，定数量，开始生成。**

### 这一步的业务意义
它不是在定义规则，而是在发起一次对规则的实际消费。

---

## 二、浏览器扩展提示区

当前代码还确认：当你选择某些需要额外能力支持的规则时，页面会出现提示，说明这批任务可能依赖：

- 浏览器扩展采集
- 扩展侧知识搜索等能力

#### 这说明什么
并不是所有主题任务都只靠插件后台自己完成。有些规则类型会进入带外部采集或扩展辅助的分支。

这对运营人员非常重要，因为它决定了：

- 为什么有些任务能立即跑
- 为什么有些任务会等待扩展环境
- 为什么有些任务的完成节奏和普通任务不同

---

## 三、任务列表区

页面下方是主题任务列表，用来观察所有已创建的主题任务。

当前已确认会显示的内容包括：

- 任务复选框（用于批量操作失败任务）
- 主题任务 ID
- 使用的规则
- 进度条
- 主题数量
- 状态 / 失败原因
- 创建时间
- 操作按钮

这说明主题任务页并不只是“状态板”，而是一个带批量恢复能力的执行管理页。

---

## 任务状态怎么理解

已确认可见的状态至少包括：

- `pending`
- `running`
- `processing`
- `completed`
- `failed`
- `paused`
- `cancelled`

### 通俗理解
- **pending**：已经创建，还没真正开始
- **running / processing**：正在执行中
- **completed**：任务完成
- **failed**：任务失败，通常需要看失败原因
- **paused**：人为暂停或中途停住
- **cancelled**：任务被取消

在实际运营中，最重要的不是记英文状态，而是分清三类：

1. 还没开始
2. 正在推进
3. 需要人工介入

## 页面上的常见操作

当前能确认的操作包括：

- 创建主题任务
- 按状态筛选任务
- 暂停任务
- 恢复任务
- 重试失败子任务
- 删除未完成任务
- 批量重试失败任务

### 批量重试为什么重要
说明系统设计默认承认：主题生产不是一次提交就一定全部成功。失败重试是正常运营动作的一部分，而不是“系统坏了才会用”。

## 标准操作任务

### 场景一：从一条正式规则生成一批主题
1. 打开主题任务页
2. 选择目标规则
3. 填写主题数量
4. 提交创建任务
5. 观察任务是否进入正常状态
6. 等待任务完成后，再去主题管理页筛选结果

### 场景二：任务卡住或部分失败
1. 先看任务状态和失败原因
2. 判断是不是扩展依赖、来源问题或能力层问题
3. 如果是暂时性问题，可先重试失败子任务
4. 如果是结构性问题，先回到上游改规则或 API，再重新跑

### 场景三：大批量任务执行中，需要人工控制节奏
1. 查看当前任务列表和状态分布
2. 对不适合继续跑的任务暂停
3. 对已经恢复条件的任务再继续
4. 不要一边跑一边随意改上游规则

---

## 做完之后，你应该看到什么

- 页面出现一条明确的主题任务记录
- 任务有进度、有状态变化
- 任务结束后，主题会进入主题管理页
- 如果失败，失败项可以被单独或批量重试

如果你创建成功了任务，但主题管理里长期没有结果，要优先检查任务状态、失败原因、上游规则和能力层配置。

---

## 常见误区

### 误区一：把主题任务当成规则配置页
主题任务页是执行页，不负责定义规则本身。

### 误区二：只看“有没有完成”，不看失败原因
失败原因很重要，它会告诉你问题是在规则来源、扩展依赖、还是能力调用层。

### 误区三：任务跑着的时候去动上游规则
这样很容易造成前后不一致。

### 误区四：主题数量一开始就开很大
第一次验证规则时，更适合先跑小批量，确认逻辑对了再放量。

---

## 上下游关系

### 上游
- 规则管理：决定任务从哪条规则开始生成
- API 设置：决定任务是否具备生成能力
- 发布规则：某些语言或策略会影响主题产出方向

### 下游
- 主题管理：承接主题任务产出的主题
- 后续文章任务或深度写作都会以这些主题为基础

### 特殊依赖
- 某些规则可能依赖浏览器扩展或扩展侧知识搜索链路

## 给 AI / 技术读者的结构化摘要

### purpose
topic jobs is the batch execution page that turns a selected rule into a tracked topic-generation task.

### entry
- menu label: 主题任务
- slug: `yali-ai-writer-topic-jobs`

### visible sections
task-creation form, extension-dependent warning area, task list with status/actions

### visible actions
create, filter by status, pause, resume, retry failed subtasks, bulk retry failed tasks, delete non-completed tasks

### output
generated topics are persisted and then surfaced in topic management

### operator principle
validate new rules with small batches first; use retries for transient failures and go upstream for structural failures
