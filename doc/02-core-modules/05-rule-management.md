# 规则管理

## 这篇文档解决什么问题

这篇文档帮助你理解：规则管理不是在写文章，而是在定义**主题的来源组织方式**。它决定系统后面会从什么样的素材模式中，批量产出可用主题。

很多人第一次接手时会误以为规则就是“文章模板”或“任务本身”。其实不是。规则更像是：**一套可重复使用的主题输入方案。**

---

## 模块用途

规则管理负责定义上游素材来源与生成条件。它是主题任务的直接前置页，也是主链路里非常关键的“输入层”。

它解决的核心问题是：

- 主题从哪里来
- 这些来源按什么规则被消费
- 每条规则后续能否被重复利用
- 哪些规则正在被任务占用、不能随意修改

它不直接生成主题，但决定主题生成的质量、范围和可持续性。

---

## 适用场景

你最适合在这些场景进入规则管理：

- 第一次搭建主题来源
- 想把不同来源的素材分开管理
- 想建立一条可反复执行的主题生产规则
- 某一类主题结果不稳定，怀疑来源组织方式有问题
- 想查看哪些规则正在被任务占用，避免误删误改

## 页面结构

## 一、规则列表页

列表页的重点不是只有“有哪些规则”，还包括“这些规则当前能不能安全动”。

页面上已确认会显示：

- 规则名称
- 任务 ID
- 规则类型
- 循环次数
- 子任务数量
- 状态
- 使用状态
- 更新时间
- 操作按钮

### 列表页能帮助你判断什么
- 目前已有多少规则
- 哪类规则最多
- 哪些规则启用中
- 哪些规则正在被任务占用
- 哪些规则可以安全编辑或删除

### 列表页常见操作
- 新增规则
- 编辑规则
- 删除规则
- 查看在用状态限制

如果规则正在被任务占用，编辑或删除按钮会被限制。这是为了避免任务执行中途换规则，导致上下游数据不一致。

---

## 二、规则编辑页

规则编辑页是这个模块的核心。页面一般分为几部分：

- 规则名称
- 规则类型
- 对应规则类型的条件区
- 目标分类
- 循环次数
- 参考资料
- 启用状态
- 保存 / 更新 / 取消操作

其中最重要的不是字段多不多，而是**规则类型不同，会决定整个页面中间区域的素材录入方式完全不同。**

---

## 支持的规则类型怎么理解

当前代码中已确认至少包含以下规则类型。

### 1. 随机选择文章
适合从分类中的文章池里随机取内容作为上游来源。

#### 适合场景
- 你已经有一定文章库存
- 想从现有站点内容中继续扩主题
- 不需要人工逐篇精挑

#### 页面特点
- 会出现分层分类选择
- 支持全选 / 全不选类操作

---

### 2. 固定选择文章
适合人工精确指定要作为来源的文章。

#### 适合场景
- 你明确知道哪些文章最值得作为来源
- 你希望主题生产严格围绕某几篇内容展开

#### 页面特点
- 有文章搜索
- 有已选文章列表

---

### 3. 上传文本内容
适合直接提供一段文本，作为后续主题生成的来源。

#### 适合场景
- 你有整理好的外部资料或文案
- 你不想先在 WordPress 里做成文章
- 你要用一批说明文、资料文作为主题来源

#### 页面特点
- 支持抓取 URL 内容
- 有可编辑文本区
- 有字符数限制提示

---

### 4. 导入关键词
适合直接从关键词列表出发做主题扩展。

#### 适合场景
- 你已有选题词库
- 想快速批量试跑主题
- 做 SEO 选题扩展

#### 页面特点
- 一行一个关键词
- 会统计数量

---

### 5. 随机分类
适合按分类本身去抽取来源，而不是按固定文章。

#### 适合场景
- 你更希望从站点分类维度做主题池扩张
- 想做更宽范围的来源抽样

---

### 6. 采集网址仿写
这是与普通素材型规则差异较大的一类。

#### 适合场景
- 来源主要是外部 URL
- 你希望采集后进入仿写链路
- 需要保留或控制图片、链接等内容特征

#### 页面特点
- 可录入多个 URL
- 会有去重说明
- 可控制是否保留图片、保留链接

这类规则通常意味着后续不走完全相同的普通主题处理逻辑，而会进入更偏仿写的专门链路。

---

## 关键设置怎么用通俗的话理解

### 规则名称
方便后续在主题任务页选择。命名建议直接体现来源特点，不要只写“测试规则”。

### 规则类型
它是整条规则的核心开关，决定中间录入区的结构和后续处理方式。

### 目标分类
它帮助系统理解这条规则预期面向哪个内容落点，也与后续分类策略有关。

### 循环次数
它影响规则后续生成时的重复或批次处理范围。不是越大越好，太大会让来源重复度上升。

### 参考资料
它能为后续提示词补充额外上下文，但不代表一定会自动变成高质量输出。

### 启用状态
只有启用的规则，通常才适合被主题任务消费。

## 标准操作任务

### 场景一：第一次建立正式规则
1. 先明确你的来源到底是文章、关键词、文本还是 URL
2. 选择最适合的规则类型
3. 把素材录完整，不要只做半套测试数据
4. 设定目标分类、参考资料和启用状态
5. 保存后回到列表确认规则已建立
6. 再进入主题任务使用它

### 场景二：已有规则很多，想做清理
1. 先看列表里的使用状态
2. 不要先删正在被任务占用的规则
3. 优先清理明显无效或长期不用的规则
4. 对正式规则保留清晰命名和来源边界

### 场景三：主题产出质量不稳定
1. 不要只看主题任务页
2. 先回到规则管理检查来源组织方式
3. 看是不是规则类型选错、素材质量差或循环设置过大
4. 再重跑一小批主题验证

## 做完之后，你应该看到什么

- 列表里有清晰可识别的规则
- 规则类型与素材形式匹配
- 启用规则可以在主题任务页中被选择
- 在用规则受到保护，避免误操作
- 下游主题任务有了明确、稳定的输入源

## 常见误区

### 误区一：把规则当成任务本身
规则是“来源定义”，主题任务才是“执行动作”。

### 误区二：为了方便，把不同来源混进同一条规则
这样会让后续排查和复用都变得困难。

### 误区三：任务运行中直接改规则
在用规则会被限制，不应绕开保护强改。

### 误区四：只看规则数量，不看规则质量
规则越多不代表越好，关键在于来源是否清晰、可复用、可解释。

---

## 上下游关系

### 上游
- 发布规则中的分类可用范围会影响这里的分类使用边界
- 某些全局策略会影响规则后续在生成时的表现

### 下游
- 主题任务：直接从这里读取规则来创建批量主题任务
- 主题管理：最终会接收规则生成出的主题
- 文章任务：会通过主题回查原始规则上下文

### 特殊链路
- 采集网址仿写类规则会进入更特殊的仿写处理分支

## 给 AI / 技术读者的结构化摘要

### purpose
rule management defines reusable source recipes for topic generation rather than article output itself.

### entry
- menu label: 规则管理
- slug: `yali-ai-writer-rules`
- states: list, add, edit

### confirmed rule types
random article selection, fixed article selection, upload text, import keywords, random categories, collect-url rewrite

### visible actions
add, edit, delete, search/select articles, fetch URL content, save via ajax, in-use protection

### operator principle
treat rules as stable upstream source definitions; do not mutate live rules casually
