# 提示词模板

## 这篇文档解决什么问题

这篇文档帮助你理解：Yali AI Writer 中的“提示词模板”不是一个只给技术人员看的隐藏机制，而是影响模型输出风格、图片提示词、编辑器助手行为和部分生成稳定性的关键控制层。

同时需要明确一点：**当前仓库快照中，菜单里已经注册了“提示词模板”页面入口，但独立视图文件并未完整出现在这份代码快照里。** 因此，本篇文档会基于当前已确认的菜单注册、图片提示词管理、编辑器助手模板管理以及相关视图来说明这部分能力。

换句话说，这篇文档写的是“当前代码里已经能确认存在的模板能力与入口”，而不是凭空推断一个不存在的页面。

---

## 模块用途

提示词模板承担的核心作用是：

1. 把系统默认写作策略进一步细化到具体 Prompt 结构
2. 控制图片提示词的风格与模板模式
3. 为编辑器助手提供预设提示词目录
4. 帮助系统在不同语言、不同任务类型下复用可维护的 Prompt 片段

如果发布规则解决的是“整体想怎么写”，那提示词模板解决的更像是“具体提示词应该怎么组织、怎么约束、怎么复用”。

---

## 适用场景

你最适合在这些情况下关注提示词模板：

- 文章大方向没问题，但模型表达风格仍不够稳定
- 自动配图质量不稳定，想调图片提示词模式
- 编辑器助手输出不符合常用写作习惯
- 想区分不同语言或不同任务类型的模板表现
- 你在做运维、培训或 AI 自动化，需要理解 Prompt 层承载在哪里

## 当前已确认的模板承载位置

### 1. 发布规则中的图片提示词模板
在发布规则页中，已确认存在与图片提示词相关的设置：

- 图片提示词模式
- 自定义图片提示词模板

这说明至少有一部分“提示词模板”能力，是以全局发布策略的一部分被运营人员直接使用的。

#### 它适合解决什么问题
- 自动配图风格不稳定
- 想让图片更符合文章内容或站点风格
- 想使用系统内置模式，而不是自己从零设计图片 Prompt

---

### 2. 图片提示词预设模式
当前代码里已确认存在若干内置图片提示词模式，例如：

- default
- flowchart
- content_match
- text_overlay

这意味着系统不是只有一个静态图片 Prompt，而是允许按不同产出目标选择不同提示模式。

#### 运营上怎么理解
- **default**：适合一般内容配图
- **flowchart**：更适合流程图、结构图类表达
- **content_match**：更强调与文章内容贴合
- **text_overlay**：更适合需要文字叠加效果的图片场景

这类模式不是“技术枚举”，而是图片生成策略的可选风格层。

---

### 3. 编辑器助手的提示词目录
当前代码中已确认，编辑器助手侧维护了一组默认提示词模板目录，覆盖的任务包括例如：

- 写段落
- 续写
- 总结
- 改写
- FAQ
- 博客标题
- 图片想法等

并且它们会按界面语言或语言分组组织。

#### 这说明什么
提示词模板不只是服务批量文章生成，也服务编辑器内的人工辅助操作。

也就是说，这部分能力同时作用于：

- 自动化生成链路
- 编辑器辅助链路

### 4. 图片提示词编辑器
当前还能确认存在一个基于 JSON 的图片提示词编辑界面，字段说明包括：

## 这类模块适合怎么理解

提示词模板页最容易被误解成“只是写几句 Prompt 文本”。实际上，它更像一层“模型输入规范化机制”。

它的价值通常体现在：

1. **稳定输出风格**
2. **降低每次手工改 Prompt 的成本**
3. **让不同任务可以复用经过验证的模板**
4. **让 AI/技术协作更容易理解系统输入结构**

---

## 标准操作任务

### 场景一：自动配图风格不稳定
1. 先回到发布规则看当前图片提示词模式
2. 优先试内置模式，而不是马上写复杂自定义模板
3. 如果内置模式不适合，再进一步编辑图片提示词模板
4. 重新验证生成结果

### 场景二：编辑器助手的常用输出不理想
1. 确认问题发生在编辑器助手，而不是批量文章链路
2. 回看助手使用的默认提示词类别
3. 优先从模板目录或语言分组角度理解，而不是只怪模型本身
4. 再决定是否要调整更细的模板内容

### 场景三：做培训或自动化接入
1. 先明确哪些模板是发布规则直接暴露的
2. 哪些模板属于编辑器助手目录
3. 哪些模板属于图片生成内置模式
4. 建立“策略层 → 模板层 → 执行层”的结构理解

## 做完之后，你应该看到什么

- 图片生成风格更可控
- 编辑器助手的常用输出更贴近预期
- Prompt 调整从“临时乱改”变成“有位置、有层次地维护”
- AI / 技术读者更容易理解系统输入结构

## 常见误区

### 误区一：把模板等同于单个文本框
模板在这里更像一套可组织、可分组、可复用的提示体系。

### 误区二：一上来就重写复杂 Prompt
很多时候先切换内置模式，效果就已经足够明显。

### 误区三：把所有问题都归咎于模板
模型质量、发布规则、参考资料、结构策略也都会影响结果。模板只是其中一层。

### 误区四：忽略当前仓库快照的边界
这份代码快照里能确认菜单注册和相关模板承载能力，但无法完整确认独立“提示词模板”页的全部最终 UI，因此文档应以已确认能力为准。

## 上下游关系

### 上游
- API 设置：决定模型是否可用
- 发布规则：决定整体策略与哪些模板会生效
- 图片 API：决定图片提示词最终能否实际生成出图

### 下游
- 自动配图
- 编辑器助手
- 部分文章或内容生成链路中的 Prompt 拼装

### 横向关系
- 与发布规则强关联，尤其是图片提示词模式
- 与编辑器助手强关联，尤其是默认提示目录
- 与图像生成能力强关联，尤其是图片模板输出格式
