# 文章任务

## 这篇文档解决什么问题

这篇文档帮助你理解：文章任务页不是“写作按钮”，而是**标准文章生成链路的执行监控中心**。

真正的入口通常发生在主题管理页中选中主题并点击“生成文章”；文章任务页则负责承接这批执行结果，展示进度、失败、详情和重试入口。

---

## 模块用途

文章任务页负责管理从主题到文章的批量生成任务。它最核心的职责包括：

1. 展示每一批文章任务的总体进度
2. 告诉你这批任务成功了多少、失败了多少
3. 允许查看子任务详情
4. 允许重试失败项
5. 允许清理无用任务记录

它更像一块“批量执行监控面板”，而不是内容创作入口本身。

---

## 适用场景

你最适合在这些情况下进入文章任务：

- 刚从主题管理发起了一批文章生成
- 想看某一批任务目前进度如何
- 某批任务失败，想看失败详情
- 需要重试失败子任务
- 需要删除过期或无用的任务记录

---

## 页面入口

- **菜单名称**：文章任务
- **页面 slug**：`yali-ai-writer-article-tasks`
- **后台 URL**：`admin.php?page=yali-ai-writer-article-tasks`

这是一个明显偏“任务监控与恢复”的页面。

---

## 页面结构

## 一、任务列表主区域

页面主体是任务列表卡片，当前已确认有刷新按钮。

列表会展示至少这些信息：

- 任务 ID
- 任务名称
- 进度统计
- 状态
- 时间信息
- 操作

### 这一块主要解决什么问题
让你快速判断：

- 哪批任务还在跑
- 哪批任务已经完成
- 哪批任务失败
- 哪批任务值得继续查看详情或重试

---

## 二、任务详情弹窗

页面中已确认有详情弹窗，用于查看某批任务的更细信息。

它特别适合处理这些问题：

- 哪些子任务失败
- 当前失败发生在哪个阶段
- 哪一篇主题对应的文章生成没成功
- 错误大致集中在什么环节

这一步很关键，因为批量任务的失败通常不是整批都坏，而是某几项子任务失败。

---

## 三、重试确认弹窗

页面中已确认有重试流程和确认弹窗。

这意味着系统预期的运营方式不是“失败了就重新整批建一次”，而是：

- 找出失败项
- 针对失败项重试
- 保留成功结果不回滚

这对批量内容生产非常重要，因为它降低了恢复成本。

---

## 页面上的常见操作

当前代码确认的操作包括：

- 刷新列表
- 查看详情
- 重试失败任务
- 删除任务
- 自动刷新正在执行中的任务状态

其中一个很实用的点是：页面会对正在处理中的任务做自动刷新，这意味着你不需要一直手动反复点刷新。

---

## 任务状态怎么理解

当前已确认的核心状态包括：

- `pending`
- `processing`
- `completed`
- `failed`
- `paused`

### 通俗理解
- **pending**：任务已创建，但还没进入真正处理
- **processing**：任务正在逐篇执行
- **completed**：整批任务已经完成
- **failed**：整批中至少有失败，需要人工介入
- **paused**：任务被暂停或处于待恢复状态

在这个页面中，最重要的不是死记状态名，而是分清：

1. 是不是还在跑
2. 是否已经可交付
3. 是否需要人工重试或排查

---

## 为什么文章任务页不负责“配置结果”

很多人看到文章任务出问题，会第一时间在这个页面里找“控制项”。但这页本身更像结果监控页，真正决定生成结果的关键参数，通常来自：

- API 设置
- 发布规则
- 提示词模板
- 规则管理提供的上游素材
- 主题管理阶段的主题质量与资料情况

所以文章任务页更适合问：

- 哪一批失败了
- 失败在哪里
- 要不要重试

而不是先问：

- 为啥风格不对
- 为啥分类不准
- 为啥文章质量不稳定

这些问题多半要往上游找。

## 标准操作任务

### 场景一：刚发起一批文章生成，想看进度
1. 打开文章任务页
2. 找到刚创建的任务组
3. 看状态和进度统计
4. 如果仍在处理中，可先观察自动刷新结果
5. 完成后再看成功率是否符合预期

### 场景二：某批任务失败
1. 打开该任务详情
2. 查看失败集中在哪个环节
3. 先判断是临时性问题还是结构性问题
4. 临时性问题可直接重试失败项
5. 结构性问题应回到上游模块修正后再重试

### 场景三：任务很多，想清理旧记录
1. 确认任务已经不再需要追踪
2. 确认删除不等于撤销已生成文章
3. 删除无用任务记录，保持页面清爽

## 预期输出

在标准链路下，这个页面所对应的最终业务结果通常是：

- WordPress 文章被创建
- 当前任务组记录成功数、失败数和状态
- 失败项可继续追踪和重试

它是“批量成文”的控制视图，而不是单篇文章编辑界面。

---

## 常见误区

### 误区一：文章失败就一定是模型问题
失败可能来自很多层：

- API 调用异常
- 素材缺失
- 参考资料不完整
- 图像链路未配置好
- WordPress 落库失败
- 上游主题质量不足

### 误区二：整批失败就整批重建
很多时候只需重试失败子任务，不必推翻已经成功的部分。

### 误区三：把删除任务理解成撤销内容
删除的是任务记录，不等于回滚已经创建的文章。

### 误区四：只盯结果，不回查上游
文章任务页看到的是症状，根因往往在上游。

---

## 上下游关系

### 上游
- 主题管理：从已选主题创建文章任务
- 发布规则：定义文章生成与发布默认策略
- API 设置：提供模型与服务能力
- 提示词模板：影响最终 Prompt
- 规则管理：通过主题回查来源素材

### 下游
- WordPress 文章
- 任务记录与失败记录
- 后续质量复盘和任务恢复动作

### 页面内隐含关系
如果当前没有任务，页面会明确把你引导回主题管理页去选择主题并生成文章，说明它本身并不是任务创建入口。

## 给 AI / 技术读者的结构化摘要

### purpose
article tasks is the monitoring and recovery page for standard article batch generation from selected topics.

### entry
- menu label: 文章任务
- slug: `yali-ai-writer-article-tasks`

### visible sections
task list, refresh control, detail modal, retry confirmation modal

### visible actions
view details, retry failed subtasks, delete task records, monitor auto-refreshing processing tasks

### key principle
this page monitors execution outcomes; it does not own most generation strategy settings

### upstream dependency map
topic management → article tasks ← publish rules / api settings / prompt templates / rule context
