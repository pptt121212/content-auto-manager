# 发布规则

## 这篇文档解决什么问题

这篇文档帮助你理解：发布规则不是一个普通设置页，而是 Yali AI Writer 的**全局默认策略中心**。它决定系统后续“写什么风格、按什么结构、落到什么分类、是否配图、是否加参考资料、是否植入品牌资料、用什么语言和角色来写”。

如果 API 设置决定的是“系统有没有能力”，那发布规则决定的就是“系统会按什么标准工作”。

---

## 模块用途

发布规则页负责管理整套系统的默认写作与发布策略。它最适合被理解成一个“全局标准定义页”。

它有两个特别重要的特点：

1. **影响范围广**：后续很多主题与文章产出都受这里影响
2. **不是单次任务专属配置**：这里的改动通常会影响后续所有新任务，而不是只影响一批文章

所以，这页不能只靠“想到什么就改什么”来使用，而要把它当成系统的统一控制层。

---

## 适用场景

你最适合在这些情况下进入发布规则页：

- 第一次初始化系统默认写作标准
- 想切换发文状态、分类方式、语言或角色
- 想调整文章篇幅、深度、受众定位
- 想开启或关闭自动配图、内链、参考资料、品牌资料
- 想切换个性结构或通用结构策略
- 发现产出文章风格不稳，想从策略层统一校准

---

## 页面入口

- **菜单名称**：发布规则
- **页面 slug**：`yali-ai-writer-publish-rules`
- **后台 URL**：`admin.php?page=yali-ai-writer-publish-rules`

当前代码还确认了若干通过同一 slug 进入的扩展动作页，例如：

- `action=manage-categories`
- `action=vector-clustering`
- `action=article-structures`
- `action=editor-assistant-settings`

这说明发布规则不仅是一个表单页，还是多个增强能力入口的中控页。

---

## 页面结构

### 1. 授权与许可相关区
页面顶部可以看到授权码验证相关入口。它更偏系统可用性前置，而不是内容策略本身。

### 2. 分类使用范围区
这一块的重点不是“选分类”，而是**限定插件允许使用哪些 WordPress 分类**。

它会影响：

- 规则管理里可选的分类
- 自动分类能力
- 后续文章归类范围

所以它本质上是一个“全系统分类边界”设置。

### 3. 主发布规则表单
这是页面主体，里面集中了写作与发布策略的大部分关键项。

---

## 主要设置组怎么理解

### 一、发布基础设置
这部分控制文章最终落地到 WordPress 时的默认行为，通常包括：

- 文章状态
- 发布时间间隔
- 默认作者
- 分类模式
- 手动分类
- 备用分类

#### 这组设置解决什么问题
不是“文章能不能写出来”，而是“文章写出来后该怎么落地、落到哪”。

#### 运营上最该先定什么
第一次初始化时，先想清楚：

- 默认发草稿还是直接发布
- 分类由人工指定还是自动匹配
- 如果自动分类不稳，有没有备用分类兜底

---

### 二、编辑器助手开关
这一块用于决定是否启用编辑器侧 AI 助手，并提供前往助手配置页的入口。

它不属于主批量生产链路，但会影响人工编辑和编辑器内辅助写作体验。

---

### 三、内容目标设置
这组通常包括：

- 目标字数
- 内容深度
- 目标受众 / 读者角色

这组设置最接近“你希望文章写成什么样”。

#### 通俗理解
- **目标字数**：控制篇幅级别
- **内容深度**：控制讲解层次
- **目标受众**：控制表达口吻和信息密度

如果你总感觉文章“对了个大概，但不像是写给目标人群的”，优先检查这里。

---

### 四、结构策略设置
页面中已确认存在结构指导总开关，以及两种主要结构模式：

1. **个性文章结构**
2. **通用文章结构**

#### 个性文章结构
适合强调当前主题的专属表达，系统通常会先为当前主题额外生成大纲，再继续写正文。

优点：
- 更贴题
- 个性更强

代价：
- 往往会多一次模型调用
- 成本和时延更高

#### 通用文章结构
适合规模化、统一化输出。系统会从结构库中选择更匹配的现成结构。

优点：
- 稳定
- 可规模化
- 更利于统一风格

前提：
- 结构库本身要有积累
- 向量与结构能力要正常

---

### 五、自动配图设置
页面中已确认有：

- 自动配图开关
- 最大配图数量
- 是否跳过第一个图片占位符
- 图片提示词模式
- 自定义图片提示词模板

#### 它真正决定什么
不是“有没有图片”这么简单，而是：

- 文章里是否尝试自动插图
- 插图数量上限
- 图片提示词以什么风格生成
- 自定义模板是否参与

#### 常见误区
开了自动配图，不代表一定能出图。前提还包括：

- 图像 API 已配置
- 提示词模板合理
- 文章输出中保留了系统可识别的图片占位符逻辑

---

### 六、内链设置
这个开关会影响是否尝试做内部相关文章推荐或链接补充。

它通常依赖：

- 向量
- 相似度能力
- 聚类或相关文章检索基础

因此它不是“勾开就一定很强”的功能，而是很依赖底层语义能力质量。

---

### 七、品牌资料设置
页面中已确认品牌资料相关开关和插入位置选项。

它适合解决的问题是：

- 文章风格不够品牌化
- 品牌信息露出不稳定
- 需要把品牌资料自动注入正文某个位置

它的本质是让品牌知识从“人工补充”变成“系统化参与”。

---

### 八、参考资料设置
当前已确认包括：

- 参考资料开关
- AI 精选召回
- 素材收集方式

#### 它影响什么
决定文章或生成链路中是否引入更多外部材料，以及引入深度有多大。

#### 为什么这组很关键
很多时候文章“能写”，但缺少信息密度；问题不一定在模型，而在参考材料没有进入 Prompt。

---

### 九、搜索意图与发布语言
这组设置会影响：

- 主题生成的方向判断
- 文章的默认输出语言
- 某些标题或结构判断方式

这意味着它不只是文章阶段生效，某些上游链路也会受影响。

---

### 十、AI 角色描述
这是非常重要但最容易被随意填写的一项。

它决定模型的写作人格、专业站位和表达角度。很多时候文章“技术上没错，但读起来不像你想要的内容”，问题就出在这里。

---

## 页面上的常见操作

当前代码中能确认的操作包括：

- 验证授权码
- 管理可用分类
- 前往编辑器助手配置
- 前往文章结构管理
- 前往向量聚类管理
- 保存全部发布规则

说明这页不仅定义规则，也承担多个增强能力入口的“总控面板”角色。

## 标准操作任务

### 场景一：第一次设定全局标准
1. 先定文章默认状态与发布节奏
2. 再定分类方式和可用分类范围
3. 再定目标字数、内容深度和受众
4. 再决定是否启用结构、参考资料、品牌资料和自动配图
5. 最后设定发布语言与 AI 角色
6. 保存后，再进入规则与主题链路测试结果

### 场景二：文章质量波动，需要统一校准
1. 先不要急着改单个主题
2. 回到发布规则页检查语言、角色、结构和参考资料策略
3. 统一修改后再跑一小批主题或文章验证
4. 观察是否恢复一致性

### 场景三：自动配图或结构策略效果不稳
1. 检查相应开关是否真的启用
2. 检查依赖能力是否已准备好（图像 API、结构库、向量能力）
3. 必要时通过本页跳转到对应增强页面继续校准

---

## 做完之后，你应该看到什么

- 后续主题与文章的整体风格更稳定
- 分类落点更符合预期
- 参考资料、品牌资料、结构与配图策略更一致
- 新任务开始明显遵循新的全局标准

如果你改了规则却发现旧任务没有表现出预期变化，要先确认它们是不是在改动之前就已创建。

---

## 常见误区

### 误区一：把它当成某一批任务的临时设置
这页的很多配置是全局默认，不是某一次任务私有配置。

### 误区二：一次性把所有增强能力全开
结构、参考资料、品牌资料、自动配图、内链都可能增加复杂度和成本。第一次最好循序渐进。

### 误区三：只看字段，不看依赖
比如：
- 配图依赖图像 API
- 内链依赖向量与相关文章能力
- 通用结构依赖结构库
- 精选召回会增加额外模型调用

### 误区四：忽视角色与语言
这两个字段对产物一致性影响往往非常大。

---

## 上下游关系

### 上游
- API 设置：提供模型、搜索、向量等能力基础
- 分类体系：影响可选分类范围

### 下游
- 主题任务：会受发布语言、搜索意图等影响
- 主题管理：主题推荐分类与下游策略会间接受影响
- 文章任务：几乎所有生成与发布默认行为都受这里控制
- 提示词模板：会与这里的策略一起作用到最终 Prompt

### 横向跳转
页面内还会引向：
- 文章结构管理
- 向量聚类管理
- 编辑器助手配置

## 给 AI / 技术读者的结构化摘要

### purpose
publish rules is the global policy center that defines default article generation and publishing behavior across the system.

### entry
- menu label: 发布规则
- slug: `yali-ai-writer-publish-rules`
- action branches: manage-categories, vector-clustering, article-structures, editor-assistant-settings

### major policy groups
publishing basics, category scope, editor assistant toggle, target length/depth/audience, structure mode, auto images, internal linking, brand profile insertion, reference material strategy, search intent, publish language, AI role, image prompt mode/template

### operator principle
configure broad defaults first, then validate with a small batch before scaling

### major dependencies
image api, vector capabilities, structure library, brand profiles, retrieval and model availability
