# 主题管理

## 这篇文档解决什么问题

这篇文档帮助你理解：主题管理不是一个“主题仓库展示页”，而是整套系统里非常关键的**主题整理与分流中心**。

主题任务页负责把主题产出来，但主题真正能不能进入写作、值不值得进入写作、是否需要补资料、是否重复、是否适合深度写作，基本都要在这里判断。

---

## 模块用途

主题管理承担的核心职责有四类：

1. **筛选**：把大量主题按状态、分类、优先级等条件筛出来
2. **治理**：做重复检测、清理、手工补充、参考资料生成
3. **检查**：看主题是否有向量、是否有参考资料、分类是否合理
4. **分流**：把合适主题送入标准文章生成或深度写作

它是主题生产后的运营控制中心，也是文章生产前最值得人工介入的一页。

---

## 适用场景

你最适合在这些情况下进入主题管理：

- 主题任务刚跑完，需要挑选主题
- 想检查哪些主题值得继续做文章
- 想去重、删重或清理低质量主题
- 想给主题补参考资料
- 想手工添加主题
- 想把一批主题推进到“生成文章”或“深度写作”

## 页面结构

## 一、高级筛选区

当前代码已确认筛选条件包括：

- 标题关键词
- 状态
- 匹配分类
- 优先级
- 是否已生成向量
- 是否已有参考资料
- 任务 ID

这说明主题管理的目标不是简单列全量，而是帮助运营从主题池里快速找到“当前可操作的那一批”。

### 这一区适合回答的问题
- 哪些主题来自哪次任务
- 哪些主题还没用
- 哪些主题已经排队或已使用
- 哪些主题没向量
- 哪些主题没参考资料
- 哪些主题优先级高

---

## 二、重复检测区

页面中已确认有：

- 相似度阈值
- 检测重复按钮
- 一键删除所有重复项

这说明重复治理不是隐藏能力，而是明确暴露给运营的日常整理动作。

### 为什么这一区很重要
主题池一旦开始批量生产，重复和近似重复几乎是必然问题。如果不在主题层治理，文章层的重复成本会更高。

### 但它也有风险
相似度阈值过低，会把“主题相近但仍值得各写一篇”的内容误当成重复项删掉。

当前已确认的批量操作包括：

- 删除选中主题
- 删除当前筛选结果
- 生成参考资料

这意味着主题管理不是只做观察，也是在这里直接做批量治理。

## 主题状态怎么理解

当前已确认的核心状态包括：

- `unused`
- `queued`
- `used`

### 通俗理解
- **unused**：还没被正式送入写作，通常最适合继续操作
- **queued**：已经进入某条后续执行链路，暂时不要重复使用
- **used**：已经被消费过，不再适合作为普通新任务入口

在页面交互中，`queued` 和 `used` 的主题通常会被禁用勾选，避免重复推进。

## 页面上的常见操作

### 1. 筛选主题
先从大池子里找到你真正想处理的一批。

### 2. 检测重复
发现高度相似或重复标题主题。

### 3. 删除 / 批量删除
清理无效、低质量或重复主题。

### 4. 生成参考资料
为下游文章生成增加上下文。

### 5. 手工添加主题
适合人工补题、快速插入临时选题或补上高价值主题。

### 6. 召回测试
检查当前主题在资料召回或相关候选结果上的表现，有助于判断下游生成是否会有足够上下文。

### 7. 生成文章
把选中的主题推进到标准文章任务链路。

### 8. 深度写作
把选中的主题推进到浏览器扩展执行的独立链路。

## 关键设置怎么用通俗的话理解

### 优先级
适合用于人工批次排序和先后选择，不只是展示字段。

### 向量状态
它会影响：
- 去重
- 结构匹配
- 相似度判断
- 召回质量
- 内链或聚类相关智能能力

没有向量时，很多智能能力只能退化运行。

### 参考资料状态
有参考资料，通常意味着下游 Prompt 能拿到更多上下文；但“有”不等于“好”，关键主题仍建议抽查。

### 匹配分类
它会影响后续文章落类与内容方向判断。如果这一列长期明显不合理，说明上游规则、分类策略或语义能力可能要回查。

## 标准操作任务

### 场景一：主题任务刚跑完，准备筛一批主题
1. 先按任务 ID 筛出这次新生成的主题
2. 看标题、分类、优先级、向量和参考资料状态
3. 先删明显重复或低质量主题
4. 必要时跑重复检测
5. 再挑选合适主题进入文章生成

### 场景二：主题池很大，想清理重复
1. 打开重复检测区
2. 设定合理阈值
3. 先看检测结果，不要盲删
4. 确认后再一键删除重复项
5. 对高价值主题保留人工判断

### 场景三：想补一批资料密度更高的主题
1. 先筛出重要主题
2. 执行生成参考资料
3. 用召回测试看结果是否合理
4. 再把资料较完整的主题推进到文章任务

### 场景四：有几条非常重要的人工选题
1. 使用手工添加主题
2. 一行一个标题录入
3. 可附共享参考资料和目标分类
4. 保存成功后回到列表
5. 再进入后续写作链路

### 场景五：准备进入深度写作
1. 只选当前真正要深挖的主题
2. 看确认弹窗提示，尤其是浏览器扩展、执行耗时、图像 API 前提
3. 确认主题不是 `queued` 或 `used`
4. 再提交深度写作

---

## 做完之后，你应该看到什么

- 主题池更干净
- 高价值主题更容易被挑出来
- 重复率下降
- 参考资料更完整
- 合适主题成功进入文章任务或深度写作链路

如果你发现文章结果不好，很多时候先回到主题管理复盘，会比直接盯文章任务更有帮助。

---

## 常见误区

### 误区一：主题一出来就直接全部生成文章
这样会把上游噪音直接放大到文章层。

### 误区二：不看向量和参考资料状态
这两项经常决定后续智能能力是否真正有效。

### 误区三：重复阈值设太低
会误删有独立价值的近似选题。

### 误区四：忽略 `queued` / `used` 的业务含义
这些状态不是装饰，而是防止重复消费的重要保护。

---

## 上下游关系

### 上游
- 主题任务：把主题产入这里
- 规则管理：通过主题来源间接影响这里的主题质量
- 发布规则 / API 设置：间接影响主题内容、分类和语义能力

### 下游
- 文章任务：标准文章批量生成入口
- 深度写作：浏览器扩展独立执行入口

### 横向依赖
- 参考资料能力
- 向量能力
- 分类策略
- 召回与相似度能力
