# 图像 API 与自动配图

## 模块用途

图像 API 与自动配图模块解决的是一个很实际的问题：文章正文能写出来，不代表内容已经具备完整可发布形态。很多内容在用户体验层面缺的不是文字，而是合适的图片。

这个模块的作用，就是把“文章中的图片需求”真正接到可执行能力上。它既包括图像服务商的接入，也包括文章生成或深度写作阶段如何把图片插入正文。

## 适用场景

- 你希望文章生成后能自动带图，而不是后期人工一篇篇补图
- 你已经在发布规则中开启了自动配图
- 你准备使用深度写作，因为深度写作确认提示已经明确要求预先配置图像 API

## 它在主流程中的位置

图像 API 不是主题来源，也不是文章入口。它通常作为主链路的增强层参与：

```text
发布规则中开启自动配图
  ↓
图像 API 提供实际出图能力
  ↓
文章生成 / 深度写作阶段将图片插入文章
```

## 页面入口

- `鸭梨AI写手 > 图像API`

此外，发布规则页中与自动配图相关的设置也会直接影响这条链路，包括：

- 是否启用自动配图
- 最大配图数量
- 是否跳过第一个图片占位符
- 图片提示词模式
- 自定义图片提示词模板

## 开始前要准备什么

1. 你已经明确哪些文章需要自动配图
2. 图像 API 服务商的密钥或接入信息已经准备好
3. 发布规则中已经决定是否要自动配图，以及配图数量策略

## 页面与配置的真实意义

这一页的重点不是“多一个接口配置”，而是让后续文章真正有图可插。它通常涉及：

- 图像服务商接入
- API Key / 模型或接口参数
- 可用状态测试

对运营人员来说，最重要的问题不是记住技术字段，而是确认：

- 这套图像能力能不能稳定出图
- 图片风格是否和站点内容匹配
- 自动配图是不是会影响发布质量与速度

## 自动配图到底怎么生效

自动配图本身并不完全在图像 API 页里控制，它是“发布规则 + 提示词模板 + 图像能力”一起完成的。

当发布规则里启用了自动配图后，文章链路会尝试根据图片占位符或图片提示词输出去生成图片。如果图像 API 没配置好，这条链路就会退化，最常见的表现是正文出来了，但配图没有落下来。

## 标准操作任务

### 场景一：第一次接通自动配图
1. 先在图像 API 页面配置服务商
2. 确认接口可用
3. 再回到发布规则中开启自动配图
4. 选一个小批量主题测试生成结果
5. 抽查图片数量、位置和风格

### 场景二：深度写作前检查图像链路
1. 确认图像 API 已配置
2. 再在主题管理中发起深度写作
3. 不要在图像链路没接通时直接跑深度写作主流程

## 常见误区

### 误区一：开了自动配图就一定有图
不一定。自动配图只是策略开关，真正落地还依赖图像 API 和图片提示词链路。

### 误区二：图像风格不对，就只怪模型
很多时候真正需要回查的是图片提示词模式、自定义模板或图像服务商能力边界。

### 误区三：第一次就把配图数量拉满
更稳妥的方式是先小批量验证，再决定是否放大数量上限。

## 上下游关系

### 上游
- 发布规则：决定是否启用自动配图与配图数量策略
- 提示词模板：决定图片提示词结构与风格模式

### 下游
- 标准文章生成
- 深度写作回写草稿

## 给 AI / 技术读者的结构化摘要

### purpose
Image API provides the concrete image-generation capability used by auto-image insertion in article generation and deep writing workflows.

### entry
- menu label: 图像API

### main dependencies
- publish rules auto-image settings
- image prompt mode/template
- article generation or deep-writing execution

### operator principle
Configure and verify image capability first, then enable auto-image behavior in publish rules, then test on a small batch.
