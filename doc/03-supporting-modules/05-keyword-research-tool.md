# 关键词研究工具

## 模块用途

“关键词研究工具”不是写文章的执行页，而是**选题池扩充和备用关键词准备工具**。

它解决的是更上游的问题：

- 某个核心词还能扩出哪些长尾词
- 不同地区和语言下，用户可能怎么搜
- 不同数据源下，同一个词会出现哪些补充建议
- 哪些挖出来的词值得留作后续规则、主题或 SEO 备用词

所以，这个模块更适合做“前置研究”，而不是文章生成中的最后一步。

## 典型使用场景

### 场景一：你已经知道一个核心产品词
比如你知道一个产品名、行业词或主题词，想继续拓出更多相关搜索表达。

### 场景二：你在做海外站或多语言站
页面本身提供地区和语言选项，不同地区下的搜索建议会不同，这时它比只看中文词更有用。

### 场景三：你想给后面的规则或主题准备备用词
结果页支持勾选、批量复制、清空，所以它很适合做“手动筛词”。

## 它在主流程中的位置

它不直接连到文章任务页，更像这条链路的前段：

```text
关键词研究 → 形成候选词池 → 建规则 / 做主题规划 → 生成主题 → 补料 / 写文章
```

也就是说，它是主内容流的“前端侦察兵”，不是最终生产动作。

## 入口路径

当前页面标题就是：

```text
Yali AI Writer → 关键词研究工具
```

页面布局分成两部分：

- 左侧主区，负责输入条件和查看挖掘结果
- 右侧侧栏，负责暂存你勾选出来的备用关键词

## 开始前要准备什么

- 至少一个基础关键词
- 后台管理权限
- 正常的网络访问能力
- 如果你要做趋势分析，还要接受 Google Trends 数据有时会因地区或数据量不足而失败

## 页面里有哪些关键设置

## 1. 基础关键词输入
你要先输入一个基础词，比如产品词、问题词或核心主题词。

如果这里为空，页面不会开始挖掘。

## 2. 目标语言/地区
页面提供多个国家和语言组合，例如：
- 中国简体
- 美国英语
- 日本日语
- 德国德语
- 法国语
- 西班牙语市场
- 阿拉伯语市场

这不是装饰项。前端会根据你选的语言，切换不同的挖掘词前缀和扩展词模板。

## 3. 数据来源
当前可勾选的数据源包括：

- 谷歌
- YouTube
- 购物
- 百度
- DuckDuckGo
- 维基百科
- 淘宝
- 360
- Bing

你至少要选一个数据源，否则页面会阻止执行。

## 4. 深度挖掘
这是本页最影响结果量的开关。

关闭时，系统只做基础级挖掘。

开启后，会额外做多种扩展，包括：
- 空格扩展
- 问题前缀扩展
- 字母后缀扩展
- 字母前缀扩展
- GEO 问题扩展
- 搜索意图修饰词扩展

所以，深度挖掘打开后，步骤数会显著增加，耗时也会变长。

## 真正的执行方式是什么

这页不是一次请求拿全部结果，而是一个**分段并发挖掘器**。

### 初始化阶段
点击“开始挖掘”后，系统会先创建一个会话 ID，然后初始化任务。

### 分段执行阶段
前端会把整个挖掘过程拆成很多小步骤，并且：

- 按数据源分别跑
- 在浏览器端组织步骤队列
- 最多并发 3 个请求
- 实时更新进度条和状态文案

### 收尾阶段
当所有步骤完成后，再统一：

- 读取临时文件中的全部关键词
- 去重
- 去掉原始基础关键词本身
- 渲染结果表格

这意味着，页面上的“进度条”不是样子货，而是真按步骤推进。

## 深度挖掘到底扩了什么

当前前端代码里，深度挖掘会按语言生成不同扩展模板。

以中文和英文为例，扩展维度包括：

- 问题词，比如“如何”“什么”“why”“how to”
- 意图词，比如“对比”“best”“review”“checklist”
- 字母扩展，a 到 z
- GEO 类问题词
- 空格后扩展

所以它更像是对搜索建议源做“裂变式采集”，不是 AI 自由发挥写联想词。

## 挖掘结果页可以做什么

## 1. 看结果总数
系统会显示去重后的关键词数量。

## 2. 勾选关键词
每一行都有勾选框，你可以手动挑出真正要保留的词。

## 3. 全选 / 取消全选
页面既有表头全选，也有专门的“全选”“取消全选”按钮。

## 4. 输出到备用关键词区
勾选后的词会自动同步到右侧文本框，每行一个。

## 5. 一键复制
右侧可以把当前选中的词直接复制到剪贴板。

## 6. 清空
可以一键清空当前选中的结果。

这说明它更偏“研究 + 人工筛选”，而不是全自动下游投产。

## 趋势分析是怎么工作的

结果表格里每行都有一个趋势分析按钮。

点击后，不会同时并发打很多趋势请求，而是进入一个**排队队列**：

- 同一时间只跑一个趋势请求
- 每次请求结束后会稍微停顿
- 这样做是为了降低被 Google Trends 限流的风险

趋势返回后，当前页面展示的是：
- 平均热度

后端实际上还能算出峰值、最低值和时间线，但前端当前主要显示平均热度，不是完整趋势图。

## 它的真实数据来源边界

这页名字叫“关键词研究工具”，但它本质上更接近“搜索建议收集器 + 简易趋势分析器”。

已能确认的真实能力包括：

- 调用多个公开建议源抓关键词建议
- 支持地区和语言
- 支持深度裂变扩展
- 支持 Google Trends 趋势请求
- 支持临时文件汇总和去重

但要注意，它不是：
- 商业级关键词难度工具
- SERP 全量分析平台
- 自动建任务页

它更适合作为插件内部的轻量研究工具。

## 和主内容流程的关系

## 对规则与主题的作用
这里挖出的词，最直接的用途是帮你扩充规则方向、备用词库和主题候选池。

## 对发布规则的作用
如果你的发布策略需要多个备用 SEO 词，这个页面很适合做人工准备。

## 对写作阶段的作用
它不会直接把关键词写回某个主题或文章任务。通常需要你自己手动复制，再放进后续配置或人工流程里。

## 常见误区与排查思路

## 误区一：以为它会自动生成主题
不会。它只负责挖词，不负责把这些词自动落成主题。

## 误区二：勾选结果后，系统会自动保存到别处
不会。当前页面的备用关键词区只是前端暂存和复制用途。

## 误区三：深度挖掘一定更好
深度挖掘会显著增加结果量，但也会引入更多噪音词。研究类场景适合开，精确找词时不一定需要一直开。

## 误区四：趋势分析失败就是页面坏了
Google Trends 这条链路本身就有地区、时间范围、数据不足、限流等不稳定因素。代码里也专门做了 cookie、预热和延时处理。

## 误区五：数据源越多越好
数据源多，结果会更杂。你应该按站点目标和语言市场来选，不是机械全开。

## 建议怎么用

- 用一个较清晰的基础词开始，不要一上来就用特别宽泛的概念词
- 海外站优先先把地区语言调准
- 先用少量数据源试探，再决定要不要做深度挖掘
- 趋势分析适合对少量候选词做二次筛选，不适合全表逐个点完

## 给 AI / 技术读者的结构化摘要

## 模块定位
- 类型：上游研究模块
- 主要目标：扩展关键词池，辅助规则和主题规划
- 输出形式：前端表格 + 侧栏备用关键词文本

## 用户可见输入
- 基础关键词
- 目标语言/地区
- 多个数据源勾选
- 深度挖掘开关

## 执行模型
- 初始化会话 ID
- 前端分段调度
- 最多 3 路并发
- 后端把每一步结果追加到临时文件
- 最终统一读取、去重、渲染

## 深度挖掘维度
- 基础词
- 空格扩展
- 问题前缀
- 字母后缀
- 字母前缀
- GEO 问题
- 意图修饰词

## 结果页动作
- 勾选
- 全选 / 取消全选
- 输出到备用关键词区
- 一键复制
- 清空
- 单词趋势分析

## 趋势分析能力
- 使用 Google Trends 数据
- 请求串行排队
- 当前前端展示平均热度
- 后端还能拿到更细的时间线数据

## 边界
- 不自动建主题
- 不直接写入文章任务
- 不提供商业 SEO 平台那种难度、竞争度、SERP 全视图
