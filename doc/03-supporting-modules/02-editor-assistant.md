# 编辑器 AI 助手

## 模块用途

编辑器 AI 助手不是批量生产链路的一部分，而是服务于人工编辑、改稿和局部内容增强的辅助模块。它的价值不在于替代整个文章流程，而在于让你在 WordPress 编辑器内，对具体段落或局部内容做更快的 AI 协作。

## 适用场景

- 你已经有文章草稿，但想快速补段落、改写或总结
- 团队需要在编辑器内进行 AI 辅助，而不是完全依赖批量任务链路
- 你希望统一常用的编辑提示词，降低人工重复操作

## 入口路径

当前这条链路的入口有两层：

1. 在 `发布规则` 页面中启用“编辑器AI助手”开关
2. 通过发布规则页中的“前往助手配置”进入助手配置页面

这意味着它先由发布规则控制是否对编辑器侧开放，再由专门配置页管理具体提示词能力。

## 开始前要准备什么

1. API 设置已经可用，因为助手实际生成仍然要依赖模型调用
2. 你已经确认自己的团队有编辑器内协作需求
3. 发布规则中已经开启编辑器 AI 助手

## 这个模块真正解决什么问题

它最常用来解决这些问题：

- 草稿有了，但某段太短，需要补写
- 语气不对，需要改写
- 内容太散，需要总结
- 需要快速生成 FAQ、标题、短段落或图片想法

也就是说，它不是从 0 到 1 建完整文章，而是从 0.6 到 0.8 或 0.9 做快速增强。

## 已确认的能力载体

从当前代码可以确认，这个模块至少包括：

- 编辑器内开关与跳转入口
- 助手配置页
- 一组可维护的默认提示词模板目录

这些模板能力已确认覆盖例如：

- 写段落
- 续写
- 总结
- 改写
- FAQ
- 博客标题
- 图片想法

并且会按界面语言或语言分组组织。

## 标准操作任务

### 场景一：先开启助手能力
1. 进入发布规则页
2. 打开“编辑器AI助手”开关
3. 通过提示区跳转到助手配置页
4. 确认默认提示词目录已满足当前编辑需求

### 场景二：统一团队常用编辑动作
1. 先明确团队最常做的是补段、改写、FAQ 还是标题优化
2. 回到助手配置页维护对应提示词
3. 再让编辑同学在实际编辑器里使用

## 常见误区

### 误区一：把它当成整篇文章生成器
它更适合局部增强，不是主批量生产链路替代品。

### 误区二：不开启发布规则就直接找配置页
当前实现里，它与发布规则中的总开关是有关联的，不建议跳过这个入口理解它。

### 误区三：所有输出问题都归咎于助手提示词
编辑器助手效果同样受 API 能力、语言设置和实际选中文本上下文影响。

## 上下游关系

### 上游
- API 设置
- 发布规则中的编辑器助手开关
- 提示词模板目录

### 下游
- WordPress 编辑器内的局部内容辅助写作

- enabled from publish rules
- configured through the linked assistant settings page

### capability style
