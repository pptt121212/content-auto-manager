# 安装与初始设置

## 文档目的

本文档用于说明，在真正开始使用 Yali AI Writer 之前，应该先完成哪些准备工作，以及建议按什么顺序做初始配置。

它不覆盖每个模块的全部细节，而是聚焦三个目标：

- 把系统从“可见”变成“可用”
- 把基础能力、规则和输入链路先接起来
- 为后续的选题、生成、深度写作和优化模块打下稳定基础

如果你把这一步做扎实，后续内容生产会顺很多。如果这一步跳过太多细节，后面的生成结果通常会不稳定。

---

## 前置条件

开始前，请确认你已经具备以下条件：

### 访问权限
- 可访问 WordPress 后台
- 可使用 Yali AI Writer 插件对应的管理入口
- 如涉及外部服务，具备相应配置权限

### 基础信息
- 已明确站点主题或业务方向
- 已知目标内容语言或主要面向市场
- 已初步确定品牌表达边界

### 外部能力准备
- 已准备需要使用的 API 信息
- 如使用扩展能力，已准备对应的 API Key 或接入信息
- 如后续需要关键词研究、搜索素材或 GSC 相关能力，应提前确认外部账户和权限是否可用

---

## 安装与初始化的总体原则

在 Yali AI Writer 中，推荐遵循这个顺序：

1. **先让系统能工作**
2. **再让系统按你的要求工作**
3. **最后再让系统工作得更好**

对应到实际操作，就是：

1. 先做插件安装与基础访问确认
2. 再做 API 设置和扩展 / API Key 设置
3. 再做发布规则与规则
4. 再做选题、生成和增强模块

---

## 初始设置的推荐步骤

## 第一步，确认插件已正确安装并可进入管理界面

### 完成标志
- 可以正常打开插件入口
- 基础页面可访问，没有明显缺失的菜单或权限问题

## 第二步，完成 API 设置

### 目的
接入系统所依赖的基础能力。没有完成 API 设置，文章生成、深度写作以及很多增强能力都无法正常运行。

### 建议检查
- 配置项填写完整
- 所需密钥或地址没有遗漏
- 后续模块依赖的基础能力已具备

## 第三步，完成扩展与 API Key 设置

### 目的
接入额外的服务能力或插件增强能力。

### 建议做法
不要一次接入所有可能的服务。优先配置当前生产链路真正依赖的能力，避免把初始化过程拉得过长。

## 第四步，建立发布规则

### 目的
明确内容的发布侧约束，让系统输出具备稳定的落地边界。

## 第五步，建立生成规则

### 目的
约束系统在内容生成过程中的行为。

### 建议做法
初始化阶段先建立一套够用的核心规则，不必追求覆盖所有特殊场景。等你跑通内容链路后，再按实际效果细化。

## 第六步，准备选题生产链路

### 相关模块
- 选题任务
- 选题整理
- 关键词研究
- 搜索素材

### 建议做法
即使在试运行阶段，也建议至少形成“任务产生主题，主题经过整理，再进入生成”的基本路径。这样更容易判断问题出在规则、输入还是写作阶段。

## 第七步，开始文章生成与深度写作

### 操作顺序建议
1. 先用文章生成形成基础稿件
2. 再根据质量要求，决定是否进入深度写作
3. 视内容成熟度，再进入编辑助手、图片和其他增强模块

## 第八步，补齐增强与优化模块

### 相关模块
- 编辑助手
- 图片
- 搜索素材
- 品牌档案
- 关键词研究
- GSC

### 建议做法
增强模块不需要在第一天全部铺满。更稳妥的节奏是，先让核心链路可用，再逐步接入这些优化能力。

---

## 初始化完成后的自查清单

### 基础接入
- 插件已启用并可访问
- API 设置已完成
- 必要的扩展 / API Key 已完成

### 规则体系
- 已建立至少一套发布规则
- 已建立至少一套核心生成规则

### 内容输入
- 已有选题任务入口
- 已能对选题进行整理
- 如有需要，已准备关键词研究或搜索素材能力

### 内容输出
- 已能进入文章生成
- 已明确何时使用深度写作

---

## 常见起步误区

### 误区一，只配 API，不配规则
这样虽然能生成内容，但输出通常不稳定，很难复用。

### 误区二，跳过选题整理，直接生成
这样容易把低质量或不清晰的主题直接带进写作阶段，后期返工会更多。

### 误区三，一开始就把所有增强模块全部接满
这样会拖慢初始化，增加复杂度。更好的做法是，先跑通核心链路，再逐步补齐。

### 误区四，把深度写作当成救火工具
如果前面的选题、规则或基础输入不清晰，深度写作也不能自动修复所有问题。
