# 安装、接入与初始配置

## 这篇文档解决什么问题

这篇文档回答的是：在你真正开始跑主题和文章之前，到底应该先把哪些基础项配置好，为什么这些东西一定要先配，以及什么叫“已经具备进入生产的条件”。

它的重点不是穷举所有字段，而是帮你把初始化这件事真正做对。

---

## 一、先确认你是不是已经具备开始配置的条件

在操作之前，你至少应该已经具备下面这些基础条件：

- 能进入 WordPress 后台
- 能看到 Yali AI Writer 主菜单
- 具备管理权限
- 已准备好所需 API 信息
- 已经知道当前站点主要做什么内容、用什么语言、面向什么人群

如果这些基础条件都还不明确，那你现在最应该做的不是继续往下配，而是先把环境和业务目标补齐。

---

## 二、初始化为什么一定要按顺序来

初始化最怕的不是慢，而是顺序错。顺序一旦错，后面的问题会不断堆积，而且你很难判断到底是哪一层出了问题。

推荐顺序是：

1. 先确认后台入口和访问权限
2. 先配置 API 设置
3. 再配置图像 API（如果后续要用配图）
4. 再配置发布规则
5. 再建立规则
6. 再进入主题任务和主题管理
7. 最后才是文章生成、深度写作和增强模块

这套顺序背后的逻辑很简单：前面的页面负责建立能力和标准，后面的页面才负责真正把内容生产跑起来。

---

## 三、先看后台菜单，你会从哪里开始

从当前菜单结构看，第一次初始化最关键的入口是这些：

- API 设置
- 图像 API
- 规则管理
- 主题任务
- 主题管理
- 文章任务
- 发布规则
- 提示词模板

它们并不是并列优先级。真正该先做的是 API 设置和发布规则，因为这两个页面分别决定“系统有没有能力”和“系统按什么标准工作”。

---

## 四、初始化第一步：API 设置

### 为什么要先做它

因为系统中的主题生成、文章生成、编辑器助手、参考资料整理、向量相关能力，都离不开 API。没有这一步，后面的绝大多数智能能力都只是空转入口。

### 这一步的目标

不是把页面填满，而是让系统真正具备稳定调用文本模型、向量模型和搜索能力的条件。

### 做完之后，你应该确认什么

- 至少有一套可用的文本 API 配置
- 如果后续要用向量能力，向量 API 已准备好
- 如果要做搜索素材，搜索相关能力已准备好

如果这一步没完成，不建议继续往下配规则和主题链路，因为后面即使页面能点，执行也很可能不稳定。

---

## 五、初始化第二步：图像 API（按需）

如果你计划在文章中使用自动配图或深度写作完成后自动回写带图内容，那么图像 API 最好在早期就配好。

这一步不是所有场景都必须先做，但如果你后面会启用自动配图，又在前期没有准备它，那么后续产物就会出现“正文链路能跑、图片链路补不上”的情况。

---

## 六、初始化第三步：发布规则

### 为什么它是初始化中的核心页面

因为它不是一个普通设置页，而是全系统默认标准的集中入口。文章状态、发布时间间隔、默认作者、分类模式、目标字数、内容深度、目标受众、结构指导、自动配图、品牌资料、参考资料、素材收集方式、搜索意图推断、发布语言和 AI 角色描述，都会在这里被统一定义。

### 第一次初始化时最应该先确定的，不是所有字段，而是这几类问题

- 文章默认发草稿还是直接发布
- 分类由人工指定还是按主题自动匹配
- 你的内容大致写给谁看，写到多深、多长
- 是否需要配图
- 是否要启用参考资料和品牌资料
- 默认语言和写作角色是什么

只要这些总方向先定下来，你后面再进入规则和主题链路时，产出的结果才会有一致性。

---

## 七、初始化第四步：规则管理

到这一步，你才开始真正定义“主题从哪里来”。规则不是文章内容本身，而是主题生产的输入组织方式。

第一次初始化时，你不需要把所有规则类型都试一遍，但至少应该建立一条你准备拿来正式测试的规则。这样后面创建主题任务时，系统才有明确的上游来源。

---

## 八、初始化第五步：主题任务与主题管理

### 为什么这两步应该连在一起看

因为主题任务负责批量生成，主题管理负责筛选和继续推进。前者解决“产出一批主题”，后者解决“哪些主题值得进入写作”。

第一次初始化时，你的目标不是追求一口气生成很多主题，而是确认：

- 规则能顺利进入主题任务
- 主题任务能跑出结果
- 主题管理页能让你看懂状态、筛选条件和可执行动作

只要这三件事成立，你的主题生产链路就算初步打通了。

---

## 九、初始化第六步：文章任务

当主题链路能稳定产出后，再进入文章任务做第一次标准出文测试。这个阶段的目标不是做复杂优化，而是验证：

- 选中的主题能否正常进入任务组
- 任务页能否展示进度、状态和错误
- 文章能否按默认规则落到 WordPress

如果这一阶段都还没稳定，就不建议把深度写作设为主路径。

---

## 十、哪些能力可以留到第二阶段再引入

当主链路已经跑通之后，再逐步引入下面这些增强能力会更稳妥：

- 深度写作
- 编辑器 AI 助手
- 品牌资料
- 搜索素材
- 关键词工具
- 文章结构、向量与智能优化
- GSC 数据洞察

这样做的好处是，你能够清楚判断每个增强模块到底给结果带来了什么变化，而不是所有变化同时发生、最后谁也说不清。

---

## 十一、初始化完成的判断标准

只有当下面这些问题你都能回答“是”时，才算真正完成了初始化：

- 我能稳定进入插件后台页面
- 我已经配好了至少一套可用的 API
- 我已经定义了发布规则
- 我已经建立了至少一条真实可用的规则
- 我能从规则跑出主题
- 我能在主题管理里筛主题并继续推进
- 我能发起至少一次标准文章生成

如果这些条件还不满足，就不要急着说“系统已经准备好了”。那通常只是“页面已经能看到了”，还不是“内容生产已经可以开始了”。

---

## 给 AI / 技术读者的结构化摘要

### purpose
定义 Yali AI Writer 的初始化顺序与最小可运行配置，避免用户在主链路未打通前过早关注高级模块。

### required setup order
admin access → api settings → optional image api → publish rules → rule management → topic jobs → topic management → article tasks

### core initialization success
用户能从规则成功推进到主题，再从主题推进到标准文章生成。

### postpone until phase two
deep writing, editor assistant, brand profiles, search materials, keyword tool, structures, vectors, gsc
