# 从接手到产出的第一条上手路径

## 这篇文档解决什么问题

这篇文档不是解释所有细节，而是告诉你：**如果你今天第一次接手 Yali AI Writer，最稳妥的上手路径是什么。**

很多人第一次接手时会做错两件事。第一，过早关注某个高级功能，比如深度写作、结构优化或自动配图；第二，把系统当成“有空再补规则和资料”的写作工具。这样做的结果通常是：前面省了时间，后面全靠返工补回来。

所以，这里给你的不是“完整说明书”，而是一条真正能落地的第一条使用路径。

---

## 第一步：先确认你接手的是“系统”，不是“按钮”

在你开始操作之前，先接受一个前提：你要接手的是一套内容生产系统。它至少包含以下阶段：

- 接能力
- 定规则
- 组织主题
- 生成文章
- 再做增强和优化

如果你跳过这个认知，后面就很容易出现一种错觉：明明按钮都能点，为什么效果却不稳定。原因通常不是按钮坏了，而是前置阶段没有完成。

---

## 第二步：先把最小可运行链路搭出来

第一次接手时，不要一上来就把所有增强模块一起开满。你应该先完成一条最小可运行链路，让系统从“存在”变成“真的能出内容”。

这条最小链路通常是：

1. 能正常进入后台主菜单
2. 完成 API 设置
3. 完成发布规则
4. 建立至少一条规则
5. 创建一次主题任务
6. 在主题管理里筛出可用主题
7. 发起一次文章生成

如果这七步还没跑通，就先不要把注意力放在深度写作、品牌资料、向量或 GSC 上。那些能力很重要，但它们不应该先于主链路本身被验证。

---

## 第三步：先分清“必须先做”和“后面再做”

### 必须先做的

这些事项会直接决定系统能不能开始正常产出：

- API 设置
- 发布规则
- 规则管理
- 主题任务
- 主题管理
- 文章任务

### 后面再逐步引入的

这些事项会显著影响质量、效率和长期运营能力，但不应该抢在主链路前面：

- 图像 API 与自动配图
- 编辑器 AI 助手
- 品牌资料
- 搜索素材
- 关键词工具
- 文章结构、向量与智能优化
- GSC 数据洞察

这个排序不是说后者不重要，而是说：它们应该在主链路稳定后引入，效果才最容易判断。

---

## 第四步：第一次上手时，应该怎么判断自己有没有走偏

第一次接手时，你可以用下面这些问题做自查：

### 我现在是不是还停留在“能进后台，但不能稳定调用能力”阶段？

如果是，那就不要跳过 API 设置和基础接入验证。

### 我是不是已经能跑出主题，但还没形成稳定的主题筛选习惯？

如果是，那就不要急着批量出文，先把主题管理页用顺手，把筛选、去重、优先级、参考资料和向量状态看明白。

### 我是不是已经开始生成文章，但还在频繁手工补规则？

如果是，那说明你的发布规则和规则管理可能还没有稳定，应该回头先把控制层打牢。

### 我是不是还没跑通标准文章生成，却已经想把深度写作当主路径？

如果是，建议先收回来。深度写作是很重要的能力，但它不应该在你连标准链路都没跑通之前承担主路径角色。

---

## 第五步：第一次接手时，最推荐的学习节奏

### 第一天：把系统跑通

目标不是写得完美，而是验证系统能不能完整跑一遍。

你应该优先完成：后台入口确认、API 设置、发布规则、规则创建、主题任务创建、主题筛选和一次标准文章生成。

### 第二阶段：把主流程用顺

当你已经确认系统能跑之后，就要开始关注两个问题：

- 上游主题够不够稳定
- 下游文章够不够一致

这时你应该重点深入：规则管理、主题任务、主题管理、文章任务、发布规则和提示词模板。

### 第三阶段：把增强能力逐步接进来

这时再去引入：参考资料、品牌资料、图像 API、编辑器助手、结构、向量、关键词工具和 GSC。这样你才能分辨增强模块到底带来了什么效果，而不是把所有变化揉在一起看不清。

---

## 第六步：第一次产出后，怎么判断自己是否可以继续放量

不要只看“文章有没有生成出来”，还要看：

- 主题是不是足够清晰和可控
- 文章是不是按你的默认规则落地
- 分类、作者、状态、篇幅和受众是不是符合预期
- 失败任务能不能看懂、能不能重试
- 你能不能清楚解释每一步为什么这样配置

如果这些问题里有一半以上你还说不清，就说明你还处在“刚跑通”阶段，而不是“可以放量”阶段。这个时候应该继续读模块文档，而不是立刻扩大生产规模。

---

## 一条最实用的建议

第一次接手时，请优先把下面这四个页面用明白：

1. API 设置
2. 发布规则
3. 主题管理
4. 文章任务

因为这四个页面分别对应：能力是否可用、系统默认标准、主题是否可进入写作、以及文章产出是否真正可控。只要这四块没吃透，其他高级能力再多也会用得很虚。

---

## 给 AI / 技术读者的结构化摘要

### purpose
定义第一次接手 Yali AI Writer 时的最小可运行学习路径，帮助用户先跑通主链路，再逐步引入增强模块。

### minimal viable path
后台入口 → API 设置 → 发布规则 → 规则管理 → 主题任务 → 主题管理 → 文章任务

### defer until later
deep writing, brand profiles, search materials, image api, editor assistant, structures, vectors, keyword tool, gsc

### success criteria
用户能够独立完成一次主题到文章的基本产出，并理解每一步的前置条件与结果。
