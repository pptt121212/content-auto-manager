# 系统概览：这套插件到底在做什么

## 这篇文档解决什么问题

很多人第一次看到 Yali AI Writer，会下意识把它理解成“一个会自动写文章的插件”。这种理解太窄了，也会直接导致后续使用顺序出错。实际上，这套插件更接近一个围绕 WordPress 内容生产搭建起来的后台系统：它不仅负责写，还负责接能力、定规则、组织主题、调度任务、补资料、回写草稿、管理增强能力，以及为后续优化提供入口。

所以，这篇文档的目标不是讲具体按钮，而是先建立一个正确的总认识：**它是一套内容生产链路，而不是一个写作按钮。**

---

## 从后台菜单看，这套插件由什么组成

从后台菜单可以看到，这套插件把内容生产拆成了一组明确页面：仪表盘、API 设置、图像 API、关键词工具、规则管理、主题任务、主题管理、文章任务、发布规则、提示词模板、品牌资料，以及通过仪表盘或直接入口进入的搜索物料和调试工具。

这个菜单结构本身就说明了一件事：系统不是围绕“单篇文章”组织的，而是围绕“**内容生产流程中的不同阶段**”组织的。你先配置能力，再定义策略，再生成主题，再让主题进入文章或深度写作，最后再用品牌、素材、图像、结构和数据做增强。

---

## 可以把它理解成五层

### 第一层：能力接入层

这一层包括 API 设置、图像 API，以及需要扩展协作时的浏览器插件连接能力。

它解决的问题不是“写得好不好”，而是“系统能不能工作”。如果这层没打通，后面的主题、文章、深度写作、搜索素材都会受影响。对运营人员来说，这一层像是开工前先把电、水、网络接好；对 AI 和技术读者来说，这一层是系统能调用外部能力的边界。

### 第二层：全局控制层

这一层主要是发布规则和提示词模板，也包括会影响规则可用范围的分类使用范围控制。

它解决的是“系统应该按什么标准工作”。比如内容默认发草稿还是发布、默认作者是谁、分类是手动还是自动、内容要写多长、针对什么读者、是否启用品牌资料、是否启用参考资料和自动素材收集、是否自动配图、是否启用编辑器助手等。你可以把这一层理解为整个系统的总开关和总约束。

### 第三层：主题生产层

这一层由规则管理、主题任务和主题管理组成。规则负责定义主题从哪里来，主题任务负责批量生成，主题管理负责筛选、去重、补资料和把主题送到下游写作。

这是整个系统最容易被低估的一层。很多人上来就想写文章，但 Yali AI Writer 的实际设计是：**先把主题做成一个可管理、可筛选、可批量推进的资产，再进入写作阶段。** 这会显著影响内容质量、一致性和可扩展性。

### 第四层：内容产出层

这一层由文章任务和深度写作构成。

标准文章生成适合插件内部统一排队、批量出文、统一跟踪进度；深度写作则是一条独立链路，插件负责发起和接收结果，浏览器扩展负责本地串行执行并回调草稿。两条链路都从“主题”出发，但它们的执行方式、等待方式、失败分支和结果落点并不完全一样。

### 第五层：增强与优化层

这一层包括图像能力、编辑器 AI 助手、品牌资料、搜索素材、关键词工具、文章结构、向量与聚类、智能优化和 GSC 数据洞察。

这一层的作用不是替代主流程，而是在主流程已经跑起来之后，把内容做得更像一个长期可运营的内容系统。它们分别解决视觉完整度、人工协作效率、品牌统一性、资料密度、关键词拓展、结构稳定性、语义能力和数据反馈闭环等问题。

## 这套插件最重要的核心对象是什么

### 规则

规则是主题生产的上游输入。它定义素材来自哪里，使用什么类型，如何被系统拆成后续可处理的主题来源。规则类型目前至少覆盖分类随机选文、固定文章、上传文本、导入关键词、随机分类和采集网址仿写。

### 主题任务

主题任务是把规则真正送进处理链路的父任务。它会根据规则和主题数量要求，推动系统批量生成主题，并把结果沉淀到主题库中。

### 主题

主题是整个系统最关键的中间资产。后续的文章生成、深度写作、参考资料补充、向量、结构匹配和部分增强能力，都围绕主题展开。可以把主题理解成“从上游信息源提炼出来、但还没进入最终文章产出的内容生产单元”。

### 文章任务

文章任务是标准出文链路中的执行容器。它会把你选中的多个主题拆成子任务，统一展示进度、成功数、失败数和重试入口。

### 发布规则

发布规则是全系统最重要的全局控制面之一。它定义的不是单一模块，而是大范围影响后续内容生成和发布行为的默认策略。

## 为什么这套系统不能跳步骤用

最常见的误区，是还没接好 API、还没定好发布规则、还没把主题链路跑通，就开始关注“为什么文章质量不稳定”。这在 Yali AI Writer 里几乎一定会出问题，因为它的很多能力是层层叠加的。

举个最实际的例子：

- 如果 API 设置没打稳，后续生成与召回就会摇摆。
- 如果发布规则没定稳，文章默认状态、分类、目标长度、受众、结构方向都会漂移。
- 如果规则和主题管理没做好，系统就不知道该围绕什么主题持续生产。
- 如果参考资料、品牌资料、结构和向量还没准备好，写出来的内容就更容易浅、散、重复或口径不稳。

所以，正确使用这套插件的方式，不是“看到哪个功能好玩就先点哪个”，而是先把主流程搭稳，再逐步引入增强能力。

## 对运营人员来说，应该怎样理解它

如果你是运营人员，最实用的理解方式是：把它看成一个“可规模化的内容生产后台”。

你不需要一开始就把所有技术实现记住，但你必须知道：哪些页面属于前置配置，哪些页面属于主题生产，哪些页面是真正出文，哪些页面是提升质量和效率的增强工具。只要这个顺序是对的，你后面的学习成本会急剧下降。

---

## 对 AI / 技术读者来说，应该怎样理解它

如果你是 AI 助手、培训资料编写者、实施人员或技术读者，你应该重点关注它的结构关系：

- 菜单与页面是什么入口
- 哪些配置是全局默认值
- 主题如何成为系统的中间对象
- 标准文章生成和深度写作分别怎么工作
- 哪些增强模块依赖主题、参考资料、向量或结构库
- 哪些模块主要服务用户操作，哪些模块主要服务系统行为

当这些结构关系清楚之后，你再去理解单个模块，就不会把文档写成“参数表”，而会更容易写成“功能契约”。

## 给 AI / 技术读者的结构化摘要

### purpose
Yali AI Writer 是一个围绕 WordPress 内容生产组织的插件系统，用于把能力接入、全局规则、主题生产、文章产出和质量增强串成一条可持续运营的链路。

### primary entry points
- 后台主菜单 `鸭梨AI写手`
- 仪表盘
- API 设置
- 发布规则
- 规则管理
- 主题任务
- 主题管理
- 文章任务

### core objects
- rule
- topic task
- topic
- article task
- publish rule

### main production flow
能力接入 → 全局规则 → 规则与主题来源 → 主题任务 → 主题管理 → 标准文章生成或深度写作 → 增强能力与优化

### supporting capabilities
image api, editor assistant, brand profiles, search materials, keyword research, article structures, vectors, clustering, gsc insights

### operator learning priority
先理解整体流程，再做初始化，再学主题链路，再学文章与深度写作，最后再学增强模块。
