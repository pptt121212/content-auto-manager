# 文章任务

## 模块用途

文章任务模块负责把“已选主题”真正变成 WordPress 文章。它是执行层模块，串联发布规则、提示词系统、AI 接口、图片处理、内链推荐和发文入库。

## 主要子功能

### 1. 任务组管理

文章任务以任务组形式运行。页面会显示：

- 任务 ID
- 任务名称
- 总主题数
- 完成数
- 失败数
- 成功率
- 更新时间
- 最后处理时间

### 2. 子任务执行

一个文章任务组内部会拆成多个子任务。失败时会保留失败子任务状态，重试时只重置失败项，成功项保持不变。

### 3. 任务详情查看

页面支持查看详情，用来排查：

- 哪些子任务失败
- 当前失败发生在哪个阶段
- 最后的错误信息是什么

### 4. 失败重试与删除

失败任务可重试。无用任务可删除，但删除属于不可撤销操作。

## 用户可以做什么

- 查看任务总体进度
- 查看成功率和失败数
- 进入任务详情排查失败原因
- 重试失败任务
- 删除无用任务
- 刷新任务列表观察后台推进情况

## 重要设置

文章任务自身是执行容器，真正影响产出的关键参数来自“发布规则”：

- 文章状态
- 发布时间间隔
- 默认作者
- 分类策略
- 目标字数
- 内容深度
- 目标受众
- 文章结构指导
- 自动配图
- 内链功能
- 品牌资料植入
- 参考资料召回
- 发布语言
- AI 角色描述

## 数据流转与模块依赖

- 主题管理 → 文章任务  
  文章任务以主题为输入，每篇文章对应一个主题记录。

- 发布规则 → 文章任务  
  文章生成前会读取唯一的发布规则记录，作为默认生成与发布配置。

- 规则管理 → 文章任务  
  文章生成时会按主题的 `rule_id` 回查源资料，用于拼装提示词。

- 提示词系统 → 文章任务  
  XML 模板处理器会把主题数据、结构、参考资料、图片指令等拼成最终 Prompt。

- API 设置 → 文章任务  
  统一 API 处理器会从激活的模型配置中取可用接口执行生成。

- 图像 API / 品牌资料 / 向量服务  
  这些能力会按发布规则中的开关决定是否参与执行。

## 操作注意

- 失败不一定都是模型问题，也可能是素材缺失、图像接口未配、引用资料不完整或 WordPress 发文失败。
- 开启个性结构、大模型精选召回、自动配图后，耗时和成本都会上升。
- 仿写规则会走特殊链路，结构策略与普通主题不同。
- 直接删任务前，最好先确认是否还需要保留排错记录。

## 什么时候使用

- 主题筛选完成，准备批量出文时
- 你要监控大批量文章生产进度时
- 某批文章生成失败，需要定位问题并重试时
