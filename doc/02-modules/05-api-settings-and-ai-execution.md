# API 设置与 AI 执行

## 模块用途

API 设置模块负责管理文本模型、预置模型、向量模型、搜索服务与 Reader 服务。AI 执行层则通过统一 API 处理器，把不同任务类型路由到正确的接口，并处理轮询、失败降级和返回结果。

## 主要子功能

### 1. 自定义文本 API

支持配置多组文本生成接口，当前可见类型包括：

- OpenAI 兼容格式
- Google Gemini
- Anthropic Claude

每组配置可设置模型、地址、密钥、温度、最大 Token、Top_p 等参数。

### 2. 预置 API

系统有预置渠道，可参与下游轮询，也可作为自定义接口失败时的兜底回退。

### 3. 向量 API

向量 API 是全系统唯一配置，用于：

- 主题向量生成
- 结构匹配
- 语义相似度计算
- 去重
- 品牌资料和参考资料召回
- 向量聚类

### 4. 搜索 API

搜索服务主要控制：

- 地区
- 最大结果数
- 安全搜索
- 时间范围
- 搜索后端

### 5. Jina Reader

Reader 服务用于网页解析，把网页转成更适合模型处理的文本格式，常与搜索或知识库召回配合使用。

### 6. 统一执行器

统一 API 处理器负责：

- 获取下一个激活接口
- 按任务类型发请求
- 记录当前任务使用的接口快照
- 处理流式与非流式请求
- 自定义接口失败时尝试预置接口兜底
- 返回 usage 信息给下游记录

## 用户可以做什么

- 新增、编辑、删除文本 API 配置
- 激活某个接口参与任务轮询
- 单独配置唯一向量 API
- 调整搜索服务默认参数
- 为不同模型类型填写对应请求参数
- 用统一执行链路为主题、文章、编辑器助手等任务提供模型能力

## 重要设置

- **is_active**：只有激活接口才会参与轮询
- **api_type**：决定请求格式和参数结构
- **model_name**：决定实际调用模型
- **temperature / max_tokens / top_p**：影响输出风格和成本
- **vector_api_type / vector_model_name**：影响整个语义空间
- **search_region / max_results / safesearch / time**：影响搜索物料结果质量
- **stream**：影响请求发送方式和超时表现

## 数据流转与模块依赖

- API 设置 → 统一 API 处理器  
  所有任务执行时，都会先从这里取可用配置。

- 统一 API 处理器 → 主题任务 / 文章任务 / 编辑器助手 / 搜索物料  
  不同任务共用统一调用层，只是 Prompt 和参数不同。

- 向量 API → 主题管理 / 文章结构 / 品牌资料 / 向量聚类  
  这些语义能力都共享同一套向量配置。

- 搜索 API / Reader → 搜索物料  
  先搜，再筛，再抓，再汇总。

## 操作注意

- 文本模型可以多套并行轮询，向量模型不要频繁切换。
- 切换向量模型后，旧向量和新向量不一定还能直接比较，语义结果可能失真。
- 激活太多质量差异很大的文本接口，会让产出风格波动明显。
- 搜索服务参数会直接影响资料召回质量，不只是“搜索页好不好看”。
- 自定义接口失败时系统可能回退到预置接口，所以排错时要确认最终实际使用了哪一套。

## 什么时候使用

- 首次部署插件时
- 需要更换模型服务商时
- 需要提高任务稳定性，做多接口轮询时
- 需要启用语义能力、搜索能力或 Reader 解析能力时
