# 规则创建与主题生产流程

## 这条流程在业务里解决什么问题

这条流程负责把“来源策略”变成“主题库存”。如果说发布规则是在定义全局写作框架，那么规则管理和主题任务，就是在回答另一个更具体的问题：**我们到底依据什么材料去生产主题。**

很多团队容易把规则理解成“写作规则”。在 Yali AI Writer 里，更准确的理解是，规则首先是**主题来源策略**。它告诉系统，你是基于站内文章、关键词、上传文本、分类，还是采集网址去生成主题。只有先把这个来源策略定好，主题任务才有稳定输入。

## 谁最常用，什么时候用

最常使用这条流程的人是：

- 运营和选题负责人
- 实施和交付人员
- 需要长期扩充内容库存的团队

最常见的使用时机有两个：

1. 你第一次搭建这套系统，准备建立自己的主题来源体系
2. 你现有主题池不够稳定，想重新优化主题生产策略

## 开始前要准备什么

开始前建议先确认：

1. `发布规则` 已经先配置过，因为发布语言、搜索意图推断和参考资料策略会影响后续表现
2. 你已经想清楚要从哪类素材生产主题
3. 你至少有一个可启用的规则来源
4. 如果规则类型依赖浏览器扩展，你知道这不是纯插件内闭环

## 这条流程的页面入口在哪里

主要会经过两个页面：

- `鸭梨AI写手 > 规则管理`
- `鸭梨AI写手 > 主题任务`

前一个页面负责定义来源策略，后一个页面负责实际创建主题生成任务。

## 第一步：在规则管理页建立来源策略

### 页面入口
`鸭梨AI写手 > 规则管理`

### 你会看到什么
规则管理页会展示规则列表，包括：

- 规则名称
- 规则任务 ID
- 规则类型
- 循环次数
- 子任务数量
- 状态
- 使用状态
- 更新时间

你也能看到两条重要业务提示：

- 修改规则后，进行中的主题任务会继续使用修改后的规则内容
- 正在被主题任务使用的规则无法编辑或删除

这说明规则不是一次性配置，而是会真实影响后续任务。

### 标准操作
1. 进入规则管理页
2. 点击“添加新规则”
3. 填写规则名称
4. 选择规则类型
5. 按类型填写对应条件
6. 如有需要设置目标分类、循环次数和规则级参考资料
7. 启用规则并保存

## 第二步：理解不同规则类型适合什么业务

当前已确认支持的规则类型包括：

### 随机选择文章
适合你希望从某些现有分类里随机抽取文章作为主题来源。常用于已有站内内容基础，想继续围绕既有内容扩展主题。

### 固定选择文章
适合你已经明确知道哪些文章值得继续衍生主题，希望围绕固定文章做稳定扩展。

### 上传文本内容
适合你手头有一段确定文本，或先通过网址采集功能抓取网页内容，再基于这段文本生成主题。

### 导入关键词
适合批量 SEO 选题场景。系统会按关键词列表和循环次数，为关键词持续生成主题。

### 随机分类
适合你希望围绕分类本身扩展主题，让系统从选定分类里随机抽取分类名称和描述来生成选题。

### 采集网址仿写
适合你手里有明确网址列表，希望抓取内容后走仿写生成链路。系统会自动做网址去重，避免重复采集。

## 第三步：填写规则时的几个关键决策点

### 决策点一：用什么来源
这决定主题质量的上限。

- 已有成熟站内内容，优先考虑文章类规则
- 已有明确关键词库，优先考虑关键词导入
- 已有文本资料，优先考虑上传文本
- 已有竞争对手或行业网址，优先考虑采集网址仿写

### 决策点二：要不要强制目标分类
如果你不选目标分类，系统会倾向智能匹配最合适分类。如果你已经明确这批主题必须归在某个分类下，就可以在规则中强制指定。

### 决策点三：循环次数要多大
循环次数不是“越大越好”。它只是放大已有来源的使用频次。来源太窄时，循环次数过高会更容易产生重复或低质主题。

### 决策点四：要不要写规则级参考资料
规则级参考资料适合放一些共通背景信息，帮助后续文章生成更准确。它不是必须项，但适合给某类主题统一补上下文。

## 第四步：在主题任务页创建真正的生产任务

### 页面入口
`鸭梨AI写手 > 主题任务`

### 页面里要做什么
1. 选择一个已启用规则
2. 填写“生成主题数量”
3. 点击“创建任务”

如果当前规则或发布设置涉及浏览器扩展参与，页面会显示提示，告诉你这条任务可能需要浏览器插件配合执行。

## 第五步：主题任务如何推进

主题任务不是一次性整包完成，而是按规则项逐步推进。每个规则项都像一个子处理单元，系统会在共享队列里逐个执行。

页面上可见的状态包括：

- `pending`
- `running`
- `processing`
- `completed`
- `failed`
- `paused`
- `cancelled`

业务上可以这样理解：

- `pending`，刚建好，还没开始
- `running` 或 `processing`，正在推进
- `completed`，这一批规则项已经处理完成
- `failed`，中途出现失败
- `paused`，被暂停
- `cancelled`，被取消

## 第六步：主题是怎么落到主题库里的

当主题生成成功后，系统会把主题写入主题表。已确认会落入的核心信息包括：

- 标题
- 内容角度
- 用户价值
- SEO 关键词
- 推荐分类
- 优先级
- 状态
- API 配置
- 向量状态
- 参考资料状态

主题刚进入主题库时，核心业务状态通常是 `unused`。这意味着它还没有被文章生成或深度写作占用。

## 第七步：自动补料分支什么时候会发生

如果满足下面两个条件，主题保存时可能自动进入参考资料收集链路：

1. 发布规则中已经启用了参考资料功能
2. 素材收集方式不是关闭状态，并且规则本身没有更直接的现成资料覆盖

此时系统会把主题的 `material_search_status` 标记为待处理，并创建对应素材搜索任务。素材来源方式已确认有两种：

- 网络搜索
- 知识库搜索，也就是浏览器扩展模式

但这里要注意，**采集网址仿写规则本身已经有内容来源时，会关闭自动搜索补料逻辑**，因为它不是空白主题。

## 什么时候说明这条流程跑通了

不是规则保存成功就算完成，而是你满足了这几个结果：

1. 规则已启用
2. 主题任务能成功创建
3. 任务能推进到完成或至少部分完成
4. 新主题已经出现在主题管理页
5. 主题字段足够支持后续人工筛选

## 常见失败点

### 1. 规则未启用或规则不存在
结果是主题任务创建失败，或者任务一开始就报错。

### 2. 规则正在使用中，却试图编辑或删除
系统会阻止，因为规则已被主题任务占用。

### 3. 来源太弱，循环次数太高
结果是主题容易重复，后续在主题管理里清理成本高。

### 4. 浏览器依赖没准备好
某些规则项需要扩展参与时，任务会进入等待浏览器采集分支，而不是在插件内直接完成。

### 5. API 返回异常
常见表现是数据格式不完整、JSON 解析失败、超时或限流。

## 下游应该怎么接

当主题任务完成后，下一站不是文章任务页，而是先进入 `主题管理`。这一步很关键，因为系统设计上明确把“生成主题”和“决定哪些主题值得写”分开了。也就是说，**规则负责生产库存，主题管理负责做运营筛选。**

## AI / 技术结构化摘要

### 业务定位
- 规则管理定义主题来源策略
- 主题任务把来源策略执行成主题库存
- 该流程是文章生成和深度写作的共同上游

### 页面路径
- 规则定义：`鸭梨AI写手 > 规则管理`
- 任务执行：`鸭梨AI写手 > 主题任务`

### 已确认规则类型
- `random_selection`
- `fixed_articles`
- `upload_text`
- `import_keywords`
- `random_categories`
- `collect_url_rewrite`

### 关键字段与对象
- 规则：名称、类型、循环次数、目标分类、参考资料、启用状态
- 主题任务：`topic_task_id` `rule_id` `status` `error_message` `subtask_status`
- 主题：标题、内容角度、用户价值、SEO 关键词、推荐分类、优先级、参考资料、向量状态

### 关键分支
- 常规插件侧主题生成
- 依赖浏览器扩展的等待分支
- 自动素材收集分支
- 采集网址仿写的现成内容分支

### 下游关系
- 输出进入主题管理
- 由主题管理决定后续进入标准文章生成或深度写作
